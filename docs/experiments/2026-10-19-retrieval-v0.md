# 후보 뽑기 실험 v0 (2026-10-19)

목적(사용자 결정): 비용 절감 확인이 아니라 **이 시스템을 쓸 때의 기대 효용을 높이는 연습** — 1종(헛짚음)·2종(놓침) 오류, 기본 비율, 조건부확률.
질문: 작은 모델이 질문 글을 보고 논리집의 상태(조각 후보) 중 들어맞는 것을 놓치지 않고 뽑는가? 판단은 그 뒤에 LLM이 한다는 전제.

## 실행
- `HF_HUB_DISABLE_XET=1 python -m experiments.retrieval_v0.run --onnx intfloat/multilingual-e5-small:onnx/model.onnx:mean:e5 --onnx Xenova/multilingual-e5-base:onnx/model.onnx:mean:e5 --onnx Xenova/paraphrase-multilingual-MiniLM-L12-v2:onnx/model.onnx:mean --onnx Xenova/bge-m3:onnx/model_quantized.onnx:cls`
- 환경: 클라우드 컨테이너 CPU 4개·메모리 15GB, GPU 없음. onnxruntime 1.31.0, tokenizers 0.23.3, huggingface_hub 2.2.0(PyTorch 없음). 학습 없이 공개 모델 그대로.
- 정답지: agent_usage 질문 131개(작업 설명) × 상태 21개, nonfiction_games 질문 22개(게임 사실 글) × 상태 15개. '예'=양성, '아니오'=음성, '일부'·'모름'은 채점에서 뺌.
- 이 환경 메모: huggingface_hub의 기본 받기 방식(xet)은 `cas-server.xethub.hf.co`가 막혀 실패 → `HF_HUB_DISABLE_XET=1`로 일반 받기.

## 읽은 것
1. **임베딩은 낱말 겹침보다 낫지만 차이가 작다.** 가장 나은 bge-m3도 agent_usage에서 k=5 재현율 33% → 41%. 큰 모델(e5-base)이 작은 모델(e5-small)보다 낫지도 않았다.
2. **놓침(2종)의 큰 몫은 모델 탓이 아니라 글에 없는 정보 탓이다.** "비슷한 과거 작업이 있다"(S_similar_past), "150턴 안쪽"(S_short), "예상 턴 수가 있다"(S_turns)는 작업 설명 글만 봐서는 알 수 없다 — 어느 방법이든 재현율이 0–44%. "웹 조사가 주된 일"(S_web)도 0%였는데, 웹 조사 기록들의 작업 설명에 '웹'이라는 말이 없었다(조사라고만 적힘). **후보 뽑기는 글에 담긴 것만 이을 수 있다** — 맥락에 있는 정보는 LLM이나 구조화된 칸이 맡아야 한다.
3. **헛짚음(1종)과 기본 비율의 실제 예.** bge-m3는 "플레이어 결과가 실제 연구에 쓰인다"(S_player_contrib)를 게임 22개 중 거의 모든 게임에서 뽑았다(아니오인 20건 중 95%). 그래서 이 상태가 뽑혔을 때 진짜일 확률 P(예 | 뽑힘)는 **10%**뿐이다. 진짜 예는 22개 중 2개(기본 비율 9%)인데, 사실 글마다 "연구"라는 말이 흔해서다. 드문 상태일수록 "뽑혔다"의 무게가 가볍다.
4. **잘 이은 곳도 있다.** bge-m3: "긴 글을 쓴다" 82%, "렌더 반복" 86%, "외부 확인" 91%, "이어서 보낸 에이전트" 72% — 작업 설명에 그 말이 비슷하게라도 들어 있는 상태들.
5. **기대 효용으로 보면 지금 논리집 크기에서는 후보 뽑기가 이득이 아니다.** 놓침을 읽기의 20배로 치면 모든 방법에서 최적 k가 10인데, 후보가 15–21개뿐이라 절반이다. 그럴 바엔 상태 전부를 LLM에게 주는 편이 단순하고 놓침이 0이다. 후보 뽑기는 후보가 수백 개를 넘을 때 다시 잰다.

## 다음에 해 볼 것 (아직 안 함)
- **글로 알 수 있는 상태만 따로 채점**: 어떤 상태가 "글로 알 수 있나"를 먼저 정해야 한다(판단이 들어가므로 기록을 남기고).
- **질문을 늘려 쓰기**: LLM이 질문 글을 한 번 풀어 쓴 뒤 뽑기(비용이 드는 대신 놓침이 주는지).
- **우리 정답지로 파인튜닝**: 판정 1,100여 개(agent_usage)로 bge-m3 또는 MiniLM을 조정 — 학습·시험을 나눠서(같은 기록으로 학습하고 시험하면 사후 설명과 같다).
- 정답지 정리: "지시서가 완전하다"(S_full_brief)는 103건 모두 예라 가려 주는 게 없다 — 논리집 쪽에서 상태를 손볼 거리.
