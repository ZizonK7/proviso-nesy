# 하위 에이전트 기록

왜: 하위 에이전트 작업마다 비용과 결과를 남겨서, 사용량 한도 안에서 작업 묶음(배치)을 계획하고 예상을 점점 맞추기 위해. batman 저장소의 AGENT-LOG 방식을 가져왔다(2026-10-14).

- **예측과 실측은 [domains/agent_usage/dispatches.toml](../domains/agent_usage/dispatches.toml)에** 적는다(2026-10-16부터, `project = "proviso"`). 보내기 전에 그 논리집으로 예측하고, 쓴 규칙·상황 값·분과 턴 범위·이유를 남긴다. 절차: [domains/agent_usage/CLAUDE.md](../domains/agent_usage/CLAUDE.md).
- **끝나면** `python scripts/agent_usage.py "<세션>/subagents/agent-*.jsonl" --md`로 실측(시간, 응답 수, 도구 호출, 캐시 생성·읽기, 입력, 출력, 합계)을 넣고 돌아본다.
- **이 파일에는** 배치마다 메인의 모델·effort, 에이전트마다 모델·effort, 검토 후 품질 점수를 적는다.

## 정의
- **난이도**: 1 아주 쉬움 · 2 쉬움 · 3 보통 · 4 어려움 · 5 아주 어려움 (보낼 때 메인의 판단).
- **예상은 분·토큰 숫자 범위로 적고, 맞았는지는 구간·등급으로 본다.** 실측은 숫자 뒤에 구간·등급을 붙여서, 예상이 맞았는지 한눈에 보이게.
  - 시간 구간 (사용자 결정 2026-10-19, 사용자가 할 일로 말한다): **잠깐** ≤ 10분 "잠깐 기다려" · **다른 일** 10–40분 "다른 거 하고 있어" · **신경 끄기** > 40분 "신경 쓰지 말고 있어". 예측 범위가 두 구간에 걸치면 사용자에게는 긴 쪽으로 말하고 `predicted.told`에 적는다. 판정은 `dispatches.py`가 예측 분 범위에서 계산한다.
  - 옛 시간 등급 S ≤ 20분 · M 20–45분 · L 45–90분 · XL > 90분은 2026-10-19 전 기록(아래 배치 1 표 포함)에만 남는다. 지난 기록은 분 숫자로 새 구간에 다시 채점했다(기록 파일의 숫자는 그대로).
  - 토큰(합계 = 캐시 생성 + 캐시 읽기 + 입력 + 출력): **T1** < 20M · **T2** 20–60M · **T3** 60–120M · **T4** > 120M
  - 예전 어림셈(응답 수 × 25만, 분당 4–5회)은 더 쓰지 않는다. 턴당 맥락은 무엇을 맥락에 두고 읽느냐가 정해서, 지금 규칙은 `agent_usage`의 R_tok_long_v5 / R_tok_short_v5 / R_resume_ctx_v2다.
- **응답 수**: 에이전트가 낸 메시지 수. **도구 호출**: Read/Write/Bash 등 사용 횟수.
- **캐시 생성**: 새로 쓰인 맥락(비쌈). **캐시 읽기**: 매 응답마다 다시 읽는 맥락(쌈). 응답이 길어질수록 커진다.
- **출력**: 글자 수 ÷ 3.6으로 추정(기록상 값은 실제보다 작음). 완료 알림의 `subagent_tokens`도 있으면 같이 적는다(생각 토큰 포함으로 보여 더 큼).
- **품질**: 메인이 검토한 뒤 1–5.

## 사용자가 정한 기본값
- 하위 에이전트 모델·effort: **Opus 5.5 (`model: "opus"`) · effort high** (사용자 지시 2026-10-14). 바꾸라고 할 때만 바꾼다.
- 사용 방침: 다음 작업부터 적극적으로 써도 되지만 억지로 쓰지는 않는다.

## 교훈 (batman에서 가져옴)
예측에 관한 교훈(L-1 확인 비용, L-2 토큰은 턴에 비례, L-4 긴 글은 나눠 저장)은 `agent_usage`의 규칙(R_verify_*, R_tok_*, R_long_doc_save)으로 옮겼고, 거기서 버전이 바뀐다. 아래는 가져온 당시의 원문이다.
- **L-1 · 비용은 쓰기가 아니라 확인에서 나온다.** "외부 시스템에서 확인"(CI, 다운로드, 실제 실행)이 들어간 작업은 쓰는 시간의 2배로 잡고 난이도를 하나 올린다.
- **L-2 · 토큰은 출력이 아니라 응답 수에 비례한다.** 매 응답마다 맥락 전체를 다시 읽기 때문. 오래 확인하는 에이전트가 비싼 건 길어서다. 맥락을 작게 유지(로그는 `tail`/`grep`, 요약본 사용). 관련 작업은 한 에이전트에 몰고 후속 지시는 같은 에이전트에 이어서 보낸다. 나누는 건 파일이 겹치지 않고 병렬로 시간을 아낄 때만.
- **L-3 · 좋은 에이전트는 지시서를 넘어선다. 지시서에 하지 말 것을 적는다.** 환영하는 추가 작업과 승인이 필요한 일을 지시서에 명시.
- **L-4 · 긴 글은 조금씩 저장한다.** 긴 문서를 한 번에 머릿속에 쥐고 있다가 실패하면 다 잃는다. 지시서에 "섹션마다 실제 파일에 이어 쓰기"를 적는다.
