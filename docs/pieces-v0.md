# 논리 조각 v0

- 작성: 2026-10-14. 지도: https://claude.ai/artifact/RCYLiDFMxsxik7dTEhjX68 (조각 문장은 이 문서가 최신)
- 목적: 앱 이름이 빠진 작은 조각으로 규칙을 쪼개, 새 상황에 대 보고(예/아니오/일부/모름 또는 값) 켜진 조각의 조합으로 결론을 내기 → 다른 상황으로 유추. 아직 코드(스키마)에는 없다.

## 원칙
- 결론마다 그 결론을 만든 조각을, 조각마다 근거를 붙인다: **근거 → 조각 → 조합 → 결론**.
- 다 붙이지 않는다. **"그 조각을 빼면 결론이 바뀌는가?"** 바뀔 때만 붙인다.
- 조각의 값은 예/아니오만이 아니다. 수량(적음/많음)도 있다(P2).
- 조각끼리 부딪히면 목표 나무로 정한다. 첫 사례: 알아서 틀기에서 "다양성" 목표가 P3(반복 경향)을 이긴다.
- 앱이 지금 어떻게 동작하는지(사실)는 코드에서 확인. 사용자에게는 의도와 판단만.

## 조각 (사용자 검토 반영)
| id | 조각 | 근거 | 변경 |
|---|---|---|---|
| P1 | 후보 목록에서 하나를 고른다 | 앱 구조 | |
| P2 | **새 항목을 추가할 수 있는 자리의 수** (적음 / 많음) | Flowlog 5칸, 알아서 틀기 30곡 | "보여 줄 칸이 적다"에서 넓힘 (사용자) |
| P3 | 같은 것을 반복해서 고른다 | Flowlog 실제 기록(1위 80%) | 유지 (사용자 확인) |
| P4 | 한 번 쓴 새 항목은 또 쓸지 아직 모른다 → 순위를 차지할 명분이 약하다 | 사용자 생각 | |
| P5 | **사용자가 방금 쓴 것을 이 목록에서 다시 만나길 기대한다.** 기대가 어긋나면 수고가 들고, 반복되면 그만둔다 | 사용자 경험(Flowlog: 기록을 안 하게 됨), 사용자 생각(알아서 틀기: 나오길 바라며 트는 건 부자연스러움) | "재입력 수고"에서 "재사용 기대"로 (사용자 근거 정정) |
| P6 | P2가 적으면 위치를 고정한다. 많으면 고정 위치 없이, 고를 때마다 점수에 약간의 운을 섞어 새 항목이 가끔 올라오게 한다 | 사용자 판정(질문 1), 알아서 틀기 실제 동작(smart.js) | "섞는다"를 실제 동작으로 구체화 |

열린 문제: P2의 적음/많음 경계(5는 적음, 30은 많음, 그 사이는 모름).
