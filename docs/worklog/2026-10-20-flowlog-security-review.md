# 2026-10-20 — Flowlog 보안 점검

에이전트: 보안 점검 (Opus 5.5, effort high). 하위 에이전트 호출: 없음. 커밋·push: 안 함.

이 보고서에는 범위·방법·발견 개수만 적는다. 저장소가 공개라서 구체 취약점·위치·값은 적지 않았고, 상세는 이 저장소 밖 임시 폴더의 결과물에만 있다(메인이 가지고 있음).

## 한 일
- 사용자 앱 Flowlog(Android, 공개 저장소)를 저장소 주인 요청으로 자체 보안 점검. 대상 파일은 읽기만 했다.
- 점검 항목 13개: git 이력의 비밀값, Firestore 보안 규칙(저장소에 있는 문서 기준), 로그인·로그아웃·계정 전환, 로컬 저장·백업, 로그, 네트워크, 외부에 열린 앱 구성 요소, 권한, WebView·딥링크, 의존성 취약점, 빌드 설정, 개인정보(저장 종류·삭제), 저장소 공개 자체의 위험.
- 결과물: 심각도 표, 항목별 상세, 공개/비공개 판단 재료, 쉬운 것부터 조치 순서. 이 저장소에는 넣지 않았다.
- 지시서 밖: 대상 폴더가 얕은 클론(일부 이력만)이어서, 전체 이력을 보려고 원격 저장소를 임시 폴더에 미러로 따로 받았다. 대상 폴더의 git 상태는 바꾸지 않았다.

## 확인한 것 (어떻게)
- `git rev-parse --is-shallow-repository` → 대상 폴더는 얕은 클론. 임시 폴더에 `git clone --mirror` → 전체 이력(모든 브랜치·PR ref)으로 검사.
- `git log --all --diff-filter=A --name-only` 로 커밋된 적 있는 파일 전체 목록, `git log --all -p` 전체를 패턴 검사(API 키, OAuth 클라이언트 ID, Firebase 도메인·앱 ID, 이메일, 개인키, 서명 비밀번호, uid 모양 문자열, 토큰). 값은 출력하지 않고 개수·커밋·파일만 봤다.
- 코드 검사는 grep 기반: 로그 호출 전수, PendingIntent 전수, 매니페스트, 빌드 설정, SharedPreferences·파일 쓰기, Firestore 경로 목록, DAO의 계정 구분 칸.
- 규칙 문서 2개를 읽고 README의 경로 목록과 대조.
- 의존성: 웹 검색 3건.

## 발견 개수
- 높음 0, 중간 2, 낮음 6, 정보 9 (총 17).
- git 이력에서 비밀값(설정 파일, 서명 키, API 키 등) 유출은 찾지 못했다. 식별자 종류만 있었다(값은 결과물에도 옮기지 않음).

## 확인 못 한 것
- 실제 운영에 배포된 Firestore 규칙(저장소의 문서만 봄; 문서끼리도 배포 상태 설명이 어긋남).
- 웹 대시보드 코드와 개인정보 처리방침 본문(다른 저장소).
- 실기기 동작(백업 포함 범위, 계정 전환 시 화면). 빌드는 돌리지 않음(지시대로).
- 공식 취약점 DB(OSV) 직접 조회: 이 환경의 프록시가 막음. 의존성 판정은 웹 검색 수준.
- 패턴에 걸리지 않는 형태의 비밀값.

## 알려진 문제
- 의존성 취약점 판정은 확신도 낮음.
- 규칙 관련 발견은 전부 "문서상"이다.

## 다음 작업자에게
- 상세 결과물은 공개 저장소에 옮기지 말 것. 조치 결과를 기록할 때도 "몇 건 고침" 수준으로.
- 고칠 곳 대부분은 Flowlog 앱이 아니라 웹 저장소의 규칙·처리방침 쪽이다. 첫 단계는 Firebase 콘솔에서 운영 규칙 확인.
- 임시 미러 클론은 세션 임시 폴더에 있다(공개 데이터, 필요 없으면 지워도 됨).
