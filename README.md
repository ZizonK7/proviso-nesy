# proviso-nesy

**SELA: Self-Evolving Neuro-Symbolic Logic Architecture**

비싼 클라우드 LLM을 부를 때마다 그 결과를 로컬에 영구 자산으로 남겨서, 쓸수록 로컬 소형 모델이 스스로 처리하는 범위가 넓어지게 만드는 실험 프로젝트입니다.

## 아이디어

- **경험 논리집**: 수학 증명처럼 딱 떨어지는 논리가 아니라, "대체로 맞지만 예외가 있는" 실제 경험을 규칙으로 저장합니다. 규칙마다 목표, 조건, 방법, 이유, 근거, 부작용, 예외가 있고, 실패에서 배운 *단서 조항(proviso)*이 붙습니다.
- **로컬 우선, 막히면 클라우드**: 평소에는 로컬 소형 모델이 논리집을 써서 답하고, 막힐 때만 클라우드 LLM을 부릅니다.
- **클라우드는 가르치고 떠난다**: 불려 온 클라우드 LLM은 답만 주지 않고, 빠진 규칙을 논리집에 기록해 둡니다.
- **쓰면서 자란다**: 사용자가 결과를 보고 "잘됐다, 아쉽다"와 그 이유를 말하면, 규칙이 고쳐지거나 새 가설이 생깁니다.

원안: [논문 초안](docs/sela-paper-draft.md) · 원안에서 바뀐 점과 이유: [지식 양식 설계 기록](docs/knowledge-format-v0.md)

## 지금 되는 것

- 경험을 파일로 저장하고 검사합니다. 분야는 Flowlog 앱의 제목 추천, 뮤직 플레이어의 알아서 틀기와 재생 순서, 그리고 하위 에이전트 사용량 예측입니다.
- **모든 주장은 가설이고 성적표를 받습니다.** "확인됨" 딱지는 없습니다. 시뮬레이션, 실제 사용 기록 재생, 실측 같은 자동 확인과 사람의 판정을 출처별로 모아 보여 주고, 사용자 판정을 가장 무겁게 칩니다. 틀리면 어느 조각이 틀렸는지 짚고, 조건을 더해 쪼갭니다.
- 규칙을 그래프로 자동으로 그립니다. 아래가 근거, 가운데가 규칙, 위가 목표입니다.
- 의도와 실제가 어긋난 곳을 찾습니다. 목표를 해치는 동작인데 "대가로 받아들인다"는 기록이 없으면 문제로 표시합니다. 첫 발견은 뮤직 플레이어의 알아서 틀기에서 같은 곡이 다시 나오는 문제였고, 앱을 고친 뒤 점검을 통과했습니다. 조건을 쪼개지 않고 숫자만 넓힌 개정이나 시험할 방법이 없는 가설은 경고합니다.
- 논리집을 LLM 도구(MCP)로 내놓습니다. 첫 실험에서는 논리집을 쓴 Claude가 세 질문 중 둘에서 사용자 판단에 더 가까웠습니다. → [실험 보고서](docs/experiments/2026-10-14-body-v0.md)
- **AI가 스스로 쌓는 논리집**도 하나 있습니다. 하위 에이전트(AI가 일을 나눠 맡기는 다른 AI)가 얼마나 걸리고 얼마나 쓸지 예측해서, "잠깐 기다려 / 다른 거 하고 있어 / 신경 쓰지 마" 중 하나와 이유를 사용자에게 말하기 위한 것입니다. 이 분야는 사용자가 판단하지 않습니다.
  - 맞았는지는 실측이 판정합니다. 가설은 세운 뒤에 나온 기록으로만 시험합니다.
  - **계산되는 논리**: 작업의 성질에 예/아니오로 답하면, 논리 조각(이유 + 조건 + 숫자)을 조합해 시간을 계산하고 근거를 보여 줍니다. 숫자에만 맞추다 논리가 깨지지 않게, 방향(늘어나나 줄어드나)과 크기를 따로 채점하고, 지난 기록의 앞 절반으로 세워 뒤 절반으로 시험합니다.
  - 아직은 모델이 손으로 한 예측이 계산기보다 낫습니다(뒤 절반 62 % 대 51 %). 그래서 보낼 때마다 둘 다 적고 승패를 셉니다.
  - batman 저장소의 지휘 모델도 이 논리집으로 예측합니다. → [agent_usage](domains/agent_usage/CLAUDE.md)

아직 로컬 모델은 없습니다. 논리집을 고치는 일은 지금은 세션 안에서 AI가 합니다(자동으로 도는 코드는 아님).

## 다음 방향: 논리 조각

규칙을 앱 이름이 빠진 작은 조각으로 쪼개고, 새 상황에서 어떤 조각이 맞는지 대 본 뒤 그 조합으로 결론을 냅니다. 충분히 잘게 쪼개면 어떤 분야든 기존 논리를 다시 쓸 수 있게 하려는 것입니다. → [논리 조각 v0](docs/pieces-v0.md)

## 실행

Python 3.11 이상이 필요하고, 추가 패키지는 필요 없습니다. 저장소 루트에서 실행합니다.

```powershell
python -m proviso validate flowlog   # 지식 파일 검사
python -m proviso graph flowlog      # out/flowlog-graph.html 생성 (브라우저로 열기)
python -m proviso check flowlog      # 성적표: 가설마다 자동 확인과 판정을 출처별로
python -m proviso audit music_player # 점검: 목표를 해치는데 받아들인 기록이 없는 것(오류), 쪼개지 않은 개정 등(경고)
python -m domains.agent_usage.dispatches  # 하위 에이전트 예측과 실측 비교 (세 마디 구간, 손 예측 vs 계산기)
python -m domains.agent_usage.predict p04 # 계산기: 상황 값으로 시간 계산, 근거 → 조각 → 숫자
python -m domains.agent_usage.holdout     # 앞 절반으로 세운 조각을 뒤 절반으로 시험
python -m unittest discover -s tests -t .
python -m experiments.run_body_v0    # 논리집 유무에 따른 Claude 답 비교 (Claude Code 필요)
```

논리집을 Claude Code의 도구로 쓰려면 MCP 서버를 등록합니다. 방법은 `proviso/mcp_server.py` 맨 위에 있습니다.

## 구조

| 폴더 | 내용 |
|---|---|
| `proviso/` | 코어. 지식 파일 읽기·검사, 성적표, 점검, 그래프, 조회, MCP 서버 |
| `domains/<분야>/` | 분야별 지식 파일(`knowledge.toml`)과 검사·시뮬레이션. `flowlog`, `music_player`, `agent_usage` |
| `experiments/` | 본체 실험 스크립트 |
| `docs/` | 원안 논문, 설계 기록, 실험 보고서, 하위 에이전트 작업 기록 |
| `scripts/` | 운영 도구 (하위 에이전트 대화 기록에서 사용량 숫자 뽑기) |
| `tests/` | 테스트 |
