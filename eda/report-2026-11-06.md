## 관찰 1: 시간 예측 오차가 0의 왼쪽에 많이 분포

### 무엇을 그렸나

사용자가 실행한 셀의 제목은 "빗나간 쪽: 실측 / 예측 가운데 값(기하 평균)"이다. Colab의 실행 번호는 `[20]`이었으며, 다시 실행하면 달라질 수 있다.

예측 하한을 L, 상한을 U, 실제 시간을 A라고 하면:

```text
예측 기준점 = sqrt(L * U)
비율 = A / sqrt(L * U)
가로축 = log2(비율)
세로축 = 해당 구간의 기록 수
bins = 30
```

이 셀은 `predicted.minutes_lo/hi`에 기록된 **손 예측**을 사용한다. 계산기 예측(`calc`)과 실측을 직접 비교한 그림은 아니다.
기존 셀은 실제 시간이 있고 예측 상·하한이 있는 기록에서 비율을 구하며, 예측 하한이 0인 기록은 비율 계산에서 제외한다.

**로컬 보관 그림**: 아래 이미지는 `out/eda_report_2026-11-06/time-error-log2-bins30.png`에 있다. `out/`은 Git 추적 대상이 아니므로 원격 저장소에서는 그림이 표시되지 않는다. 원본·캡처는 `out/`에 유지한다. 다시 그릴 때는 위에 적은 ZIP 생성 시각·원본 커밋의 데이터와 `eda/start.ipynb`의 "빗나간 쪽: 실측 / 예측 가운데 값(기하 평균)" 셀을 참고해 bins를 30으로 설정한다. 원본 커밋만으로 당시 미커밋 변경과 Colab 데이터 상태까지 같아진다고 보장하지 않는다.

### 관찰과 해석

- 사용자 관찰: bins를 30으로 바꾸니 분포가 더 명확해 보였고, "왼쪽으로 뚱뚱한 경향"이 있다.
- 공유한 그림에서 0 미만에 기록이 많이 모여 있다. **예측 기준점보다 실제 시간이 짧은 기록이 많은 경향**, 즉 시간을 길게 예상하는 경향으로 해석한다.
- 가로축 −1은 실제 시간이 예측 기준점의 절반, +1은 두 배라는 뜻이다.
- 0은 실제 시간과 예측 기준점이 같은 지점이다. 0에서 벗어났다는 사실만으로 예측 구간을 벗어났다고 판단하지 않는다.
- 여기서의 "왼쪽"은 0을 기준으로 한 기록의 분포에 대한 시각적 관찰이다. 통계적 왜도나 정확한 과대예측 비율을 계산한 결과는 아니다.

## 표 읽기 / 해석상 주의: 규칙별 사용과 틀림 지목

노트북의 `# 규칙별: 예측에 쓴 횟수 vs 틀렸다고 지목된 횟수 (review.wrong)` 셀이 무엇을 세는지 정리한다. **실제 출력 표는 아직 공유받지 않았으므로, 이 절은 새로운 분석 결과가 아니라 표를 읽는 안내다.**

| 칸 | 코드에서 세거나 계산하는 것 |
|---|---|
| `쓴 횟수` | `predicted.rules`에 해당 규칙이 참조된 행 수 |
| `틀림 지목` | `review.wrong`에 해당 규칙이 참조된 행 수 |
| `틀림 비율` | `틀림 지목 / 쓴 횟수`. 사용 횟수가 0보다 클 때만 계산하며 소수 둘째 자리로 반올림 |

`dispatch_rules`는 보낸 일 기록의 규칙 참조를 한 행씩 펼친 표다. 따라서 여기서의 횟수는 **작업 기록에 남은 규칙 참조 횟수**이며, 규칙 자체를 독립적으로 시험한 횟수가 아니다. 셀은 규칙별로 두 종류의 참조를 합치고 없는 횟수는 0으로 채운 뒤, `쓴 횟수`가 많은 순서로 상위 20개를 보여 준다. 사용 횟수가 0인 규칙은 비율이 결측값(`NaN`)으로 남는다.

`review.wrong`은 예측 후 돌아보기에서 검토자가 틀렸다고 지목한 기록이다. 자동으로 규칙의 오류를 입증한 결과가 아니다. 표의 `틀림 비율`도 실제 오류율이나 그 규칙의 인과적 기여도를 뜻하지 않는다. 여러 규칙이 한 예측에 함께 쓰일 수 있고, 돌아보기에서 지목이 빠지거나 규칙마다 지목하는 기준이 다를 수 있다. 또한 이 셀은 같은 기록에서 사용과 지목이 짝지어졌는지 확인하지 않고 각각 합산한다.

가령 **가상의 예시로**, 사용 참조 20회와 틀림 지목 3회라면 비율은 `0.15`(15%)다. 이는 기록된 두 횟수의 비일 뿐, 독립된 시험 20번 중 규칙이 3번 틀렸다는 증명은 아니다.

이 표는 어떤 분류와 관련 기록부터 자세히 들여다볼지 후보를 고르는 데 쓸 수 있다. 사용 순위는 성능 순위가 아니며, 이 표만으로 규칙을 삭제하거나 계산기를 조정하지 않는다. 후보를 고른 뒤에는 당시 작업 성질, 함께 쓴 규칙, 예측과 실측, 지목 이유를 대조해야 한다.
