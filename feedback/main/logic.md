# 메인 피드백 — 논리집 쌓기 (가설·규칙·조각·시험)
키워드: 논리집, 가설, 조각, 계산기, knowledge.toml
읽는 때: knowledge.toml에 가설·규칙·조각을 세우거나 고치기 전, 계산기·모델을 만들기 전.

- **F082** 실패를 만나면 먼저 가른다: 자주 일어나고 이유 안의 가정이 틀렸으면 새 버전, 이유는 맞는데 드문 바깥 상황이면 예외 — 예외로 적었던 것이 사실은 규칙 수정이었다. (사용자, 2026-10-14)
- **F083** 규칙마다 목표(왜 하나)와 이유(왜 통한다고 믿나)를 적는다 — 이유가 있어야 예외의 자리가 보인다. (사용자, 2026-10-14)
- **F084** 규칙 후보의 "그 방법을 고른 이유"가 조건과 겹치면 선택 편향 의심 — 사용 습관을 능력으로 배울 뻔했다. (사용자, 2026-10-14)
- **F085** 가설은 세운 뒤 기록으로만 시험한다. 모델을 만들기 전에 까닭과 시험 기준을 먼저 적고, 지난 기록을 채울 때는 결과를 가린 작업자가 한다 — 사후 설명을 예측으로 착각할 뻔한 일이 셋. (실측, 2026-10-14~11-04)
- **F086** 상태(스위치)는 누구나 같은 답을 낼 사실로 묻는다 — 막연한 스위치는 241건 중 240건이 '예'였다. (실측, 2026-11-03)
- **F088** 방향 예측에 같은 스위치 층을 쓰지 않는다. 지시서에 "미래 정보를 어떻게 막았는지 적어라" — 시기를 못 보면 평균은 과거다(동전보다 나빴다). (실측, 2026-10-21·11-04)
- **F074** 생성자와 같은 모델의 검토는 가장 가벼운 출처로 — 자기 생성분 84 % vs 남의 것 51 %. (실측, 2026-11-03)
- **F050** 생성자의 자기평가 점수는 판정에 쓰지 않는다 — 6쌍이 모두 같은 점수였다. 거르려면 기준을 가진 별도 단계. (실측, 2026-11-03·05)
