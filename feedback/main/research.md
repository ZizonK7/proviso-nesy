# 메인 피드백 — 웹 조사 보내기
키워드: 조사, 웹, 원문, 검색, 고증, 후기, 논문
읽는 때: 조사(웹·문헌·사례) 지시서를 쓰기 전. 클라우드 `searching` 세션이면 [cloud.md](cloud.md)도.

- **F022** 검색 요약만으로 쓴 보고서는 근거로 쓰지 않는다. 원문을 열게 하고 못 연 것은 "열지 못함"으로 표시하게 한다 — 요약만 쓴 보고서에서 앱 혼동·기사 오독·AI 글 인용·판정 뒤집힘이 나왔다. (실측, 2026-10-22)
- **F023** 전송 조건을 숫자로 적는다: '원문 n건·그림 n장을 실제로 본 뒤에만 보낼 것', 질문이 여럿이면 '질문별 원문 n건' — 없으면 1차가 3~4분에 얕게 온다. (실측, 2026-10-22)
- **F024** 1차 자료가 필요하면 '1차 자료(법령·당시 간행물) n건'을 따로 적고 항목마다 '근거 → 결론' 순으로 — '원문'만 적으면 위키백과로 채운다. (실측, 2026-10-29)
- **F029** 웹 조사 지시서에 "curl + 텍스트 추출로 읽는다"를 적는다(WebFetch는 프록시를 안 탄다). 거부 사이트 목록은 [docs/dispatch.md](../../docs/dispatch.md). (실측, 2026-10-22)
- **F030** 원문이 꼭 필요한 논문 PDF는 pdftotext가 있는 세션이나 사용자 PC에서 — searching에서는 바이너리로 와 못 읽는다. (실측, 2026-11-04)
- **F033** 보내기 전에 "답이 어디에 있을까"를 묻는다 — 드문 사람·공개 통계 없는 질문은 팀을 보내도 비고 끝난다. 이름을 먼저 묻거나 원자료를 주거나 질문을 바꾼다. (실측, 2026-11-05)
- **F035** 후기 갈래는 열리는 곳(브런치·네이버 블로그 공개 글·포럼)을 이름으로 적는다 — Reddit·카페·오르비는 막혀 두 번 비었다. (실측, 2026-10-22·11-05)
