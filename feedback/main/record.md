# 메인 피드백 — 기록 (dispatches.toml · AGENT-LOG · 브랜치)
키워드: 기록, 실측, 번호, 브랜치, 병합
읽는 때: `record send`/`record finish`를 하거나 기록 파일을 손으로 만지기 전, 브랜치를 합치기 전.

- **F007** 짧아도 `record send`부터 — 보낸 뒤 적은 예측은 예측이 아니다(`written_before = false`). 사용자가 짚었다. (사용자, 2026-11-04)
- **F052** 작업자가 끝나면 사용자에게 결과를 말하기 전에 `record finish`부터 — 컨테이너가 회수되면 대화 기록이 사라진다. (실측, 2026-11-02)
- **F053** 실측은 id를 찾아 그 블록 뒤에 넣는다. `cat >>`로 끝에 붙이면 엉뚱한 기록 아래로 들어간다. (실측, 2026-10-28)
- **F056** 다른 세션과 같은 날 기록하면 기본 브랜치의 마지막 번호 다음부터. 합칠 때 뒤 묶음을 다시 매기고 원 번호를 주석으로 — 번호가 세 번 겹쳤다. (실측, 2026-10-25~11-05)
- **F058** `record finish`를 먼저, 커밋은 그 뒤 — git 숫자는 보낼 때 기준과 finish 때를 견준다. (AI 판단, 2026-11-05)
- **F109** 충돌을 풀면 `<<<<<<<` 0건과 검사 종료 코드를 본 뒤에만 add·continue·push — 표시가 남은 파일을 push했다. (실측, 2026-11-07)
