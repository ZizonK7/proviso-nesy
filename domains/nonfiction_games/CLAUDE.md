# domains/nonfiction_games/ — 비문학 기반 게임의 성공 논리

잘 된 게임(특히 책·논문·기록이 바탕인 것)의 성공 논리를 쪼개, 비문학에 대 볼 수 있게 하는 논리집. 2026-10-19에 만들었다.
배경과 사례 조사: [docs/nonfiction-games-v0.md](../../docs/nonfiction-games-v0.md). 방향과 사용자 결정은 루트 CLAUDE.md "새 방향".

## 파일
- `knowledge.toml`: 목표 3, 상태 15(게임에 대 보는 성질), 사실 29(원문 확인), 가설 9, 규칙 5.
- `games.toml`: 게임마다 **대 보기(상황 값) + 반응** 한 묶음. 덧붙인 순서대로 둔다(agent_usage의 `dispatches.toml`과 같은 구조).
- `games.py`: 기록 검사 + 게임 × 상태 표. `python -m domains.nonfiction_games.games`
- `checks.py`: 가설을 게임 기록으로 판정. **세운 뒤에 덧붙인 기록으로만 시험한다**(`SEEN_UNTIL`). `python -m proviso check nonfiction_games`

## 출처 규칙
- **사실**: 원문에서 확인한 것만(위키백과 원문, 개발자 발언, 제작자 페이지, Steam 평가 API). `checked` 날짜와 `source`를 붙인다. 게임 동작도 사실이다 — 사용자에게 묻지 않고 출처에서 확인한다.
- **대 보기 값**: 사실에서 확인되는 것만 예/아니오/일부. 확인 못 한 건 "모름"(표의 ?). 모름을 채울 때는 사실부터 더한다.
- **반응**(`outcome`): 해 본 게임은 사용자 판단(`judged_by = "user"`), 아니면 대중·전반 평가(`"public"`, 판정은 AI, 근거 숫자를 `basis`에). 사용자 결정 2026-10-19.
- **관찰**: 사용자가 그 게임을 하며 겪은 것. 아직 없다(심즈 질문에 답을 받기 전).
- **가설·규칙**: AI가 성공 사례에서 뽑은 **사후 설명**이다. 규칙은 모두 `status = "hypothesis"`이고, 망한 게임 기록으로 시험해 통과해야 `verified`로 올린다. 규칙 문장에는 게임 이름을 넣지 않는다(조각 방향).

## 순서 (사용자 결정 2026-10-19)
성공 사례로 논리를 먼저 세운다 → 망한 게임에 대 본다 → 피드백으로 더 쪼갠다. 넓히기 전에 조사 보고서의 게임들로 먼저 만든다.
- 망한 게임을 덧붙일 때: `games.toml` 끝에 이어 쓰고 대 보기는 사실로만 채운다. 그러면 `check`가 그 기록들로 가설을 판정한다. 반박되면 agent_usage의 "따라 할 방식"(개정인지 예외인지 가르기, 조건으로 올리기)대로 고친다.
