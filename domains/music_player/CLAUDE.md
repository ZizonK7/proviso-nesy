# domains/music_player/ — 뮤직 플레이어 '알아서 틀기'

사용자의 앱 music_player(github.com/ZizonK7/music_player, 비공개)의 알아서 틀기 폴더에 대한 지식. 본체 실험 v0 질문 1을 조각으로 다시 분석하면서 만들었다(2026-10-14).

- 앱 동작(사실)은 사용자에게 묻지 말고 `src/js/smart.js`와 `DECISIONS.md`에서 확인한다. 사실 노드에는 확인한 커밋을 적는다.
- **의도와 동작의 차이 → 고침 (2026-10-14)**: 사용자 의도 "알아서 틀기에서 같은 곡이 나오면 안 된다(다양성)". 이전 앱(@71f7460)은 직전 10곡만 막고 20곡씩 끝없이 이어 붙여 같은 곡이 다시 나왔다 → `audit`이 잡음 → 사용자 결정(바퀴 단위, 최대 30곡씩, 무한히 듣기 기본 켬)대로 music_player @b401048에 고쳐 push(DECISIONS.md 24번). 이제 `audit` 통과.
- 남은 확인: 실제 앱(exe/폰)에서 써 본 사용자 평가. 그 전까지 R_M1b는 가설.
- **폰 셔플 표시 (2026-10-19)**: 사용자 경험 "폰에서 가끔 순서가 갑자기 무작위, 표시 없음"(O_shuffle_surprise) → 코드 확인: 폴더의 셔플이 켜진 채 저장되고 폰 재생 막대에선 셔플 버튼을 늘 숨김 → 사용자 결정 "계속 켜 두되 표시"(G_mode_visible, R_S1) → music_player @25d6b74(DECISIONS.md 25번). 분야 범위가 알아서 틀기에서 재생 순서 전반으로 넓어졌다. 실제 폰 확인 전이라 R_S1은 가설.
- music_player 로컬 클론은 이 PC에 없다. 고칠 일이 있으면 임시 폴더에 받아 작업하고 main에 push(사용자 요청 방식).
- 비공개 저장소의 코드를 옮겨 적지 않는다. 동작을 문장으로 요약만.
