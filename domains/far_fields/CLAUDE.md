## 파일
| 파일 | 무엇 |
|---|---|
| `knowledge.toml` | **자동 생성** (`python -m domains.far_fields.build`). 손으로 고치지 않는다 |
| `fields.json` | 1차 분야 목록 399개(ko·slug·group). Opus가 400개를 뽑고 다우징(유사과학)을 뺐다 |
| `fields2.json` | 2차 분야 목록 400개(slug = 묶음 코드 + 번호, 예 `sea2_01`). 메인이 골랐다. 부적·사주·타로·관상·기 치료는 근거가 없어 뺐다 |
| `check_agent_json.py` | 2차 작업자 결과(`out/far_fields/agent_gen/<slug>.json`)의 모양 검사 |
| `shapes.py` | 모양 단어장 36개 = 상태 노드. 조각의 `conditions`가 이것을 가리켜 분야 사이가 그래프로 이어진다 |
| `generate.py` | 생성·검토 프롬프트와 배치 제출·받기·비용 집계. 키는 환경 변수 `API`로만(`scripts/claude_http.py`) |
| `extract_haiku.py` | gemmin 저장소 Haiku 웹 조사 md 10개를 같은 JSON으로 옮기기(낱말 그대로) |
| `build.py` | `out/far_fields/*.jsonl` → `knowledge.toml` |
| `connect.py` | 연결 실험 (무작위 두 조각) |
| `checks.py` | 자동 검사 없음. `AUDIT`: 일반화 문장에 분야 낱말이 새면 경고 |

원본 API 응답은 `out/far_fields/`(git 제외)에만 있다. 컨테이너가 회수되면 사라지므로 `knowledge.toml`이 남는 기록이다.

## 조각 양식 (가설 노드 하나)
- `text`: **분야·직업·도구·재료·동물 이름이 없는 일반화**. 조건 → 결론 → 이유가 보이게. 연결 실험은 이 칸을 쓴다.
- `source`: `AI 생성: claude-opus-5-5 배치 …, 출처 없음(모델 지식)`(1차) 또는 `AI 생성(Opus 5.5, Claude Code 서브에이전트) …, 검토 없음`(2차, `test_plan` 붙음) 또는 `웹 조사: Haiku 5.5 'searching' …, 원문 열람 / 검색 요약만 / 출처 없음 — <출처>`.
- 분야 칸: `field`, `group`, `rule`(그 분야 말로 쓴 경험칙), `why`, `breaks`(깨지는 조건), `confidence`(생성자 자기 표시), 고쳤으면 `general_original`.
- `conditions`: 모양 1~3개(검토자가 고친 목록이 먼저).
- `[[judgment]]` source = `"ai"`, verdict = 지지/일부/반박, note = 검토 이유. **유일한 성적.**

## 설계 결정과 이유
- **한 분야 폴더에 모두**: 409개 분야를 폴더로 나누면 `domains/`가 묻힌다. 모두 같은 일(재료 쌓기)이고 같은 출처 등급이다.
- **가설(text)로, 규칙(method)으로 넣지 않음**: 조각의 핵심은 분야 없는 주장이고, 방법은 분야 말(`rule`)에 묶여 있다. 깨지는 조건을 예외 상태로 만들면 상태가 수천 개가 되어 그래프에서 아무것도 안 이어진다 → 공유하는 것은 모양 36개뿐.
- **출처 등급**: 전부 AI 판단(가장 가벼움). 스키마의 판정 출처에 '웹 문헌'이 없어서 Haiku 조사분의 원문 열람 여부는 `source` 글에만 적었다(루트 '다음 할 일 3'의 출처 종류·근거 강도가 스키마에 들어가면 옮긴다). 무게 차이: 웹 열람 > 검색 요약 ≈ Opus 생성.
- **검토는 생성자와 같은 모델**: 따로 돌린 Opus 5.5 검토라도 같은 모델이라 후하게 나올 수 있다. 실제로 Opus 생성분은 지지 84%, Haiku 웹 조사분은 지지 51%였다(웹 조사분 일반화가 짧고 '왜'가 빠진 것이 많았던 탓도 있다). 판정은 '검토자가 아는 한 통용되는 경험칙인가'이고 현장 확인이 아니다.
- **반박도 지우지 않는다**: 판정과 함께 남긴다(사용자 원칙: 안 된 것도 어디까지 해 봤는지 남긴다).
- **진료·안전 지침이 아니다.** 생성 지시서에 위험한 절차의 자세한 방법은 쓰지 말라고 넣었다.

## 지킬 규칙
- `knowledge.toml`은 손으로 고치지 않는다. 고칠 것이 있으면 jsonl을 다시 만들거나 `build.py`를 고친다(원본 jsonl이 없으면 — 컨테이너 회수 뒤 — toml을 직접 고치되 이 문서에 적는다).
- 사용자가 그 분야를 실제로 하게 되면: 그 분야 조각에 `[[judgment]]` source = "user"를 붙이거나, 그 분야를 제 폴더로 옮겨 사용자 경험 위에서 다시 시작한다.
- 다른 분야(사용자 생활)로 옮긴 조각은 그 분야에서 다시 가설로 시작한다(루트 '큰 그림').
- 테스트 `tests/test_far_fields.py`가 막는 것: 모든 조각에 text·source·분야 칸, 1차분은 AI 판정·2차분은 판정 없이 test_plan, 모양은 단어장 안, 분야 낱말 새는 조각 5% 미만.
