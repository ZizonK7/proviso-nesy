# domains/ — 분야별 플러그인

분야 하나 = 폴더 하나. 각 폴더에:
- `knowledge.toml` — 그 분야의 목표·상태·사실·관찰과 가설(규칙 = 방법이 붙은 가설), 판정 기록 `[[judgment]]` (칸 설명은 [proviso/CLAUDE.md](../proviso/CLAUDE.md))
- `checks.py` — `CHECKS = {이름: 함수}`와 `SOURCE`(자동 검사의 출처: "measured" 실측, "simulation" 시뮬레이션 등; 없으면 "auto"). 규칙·가설의 `check` 칸이 이 이름을 가리킨다. 함수는 인자 없이 또는 노드 id 하나를 받아 `(판정, 설명)`을 돌려준다.
- 필요하면 시뮬레이션 등 분야 전용 코드
- `CLAUDE.md` — 그 분야의 출처와 현재 상태

모든 살아 있는 가설은 시험 수단을 갖는다: 자동 검사(`check`)나 판정 기록(`[[judgment]]`). 둘 다 없으면 `audit`이 "시험 수단 없음"으로 경고한다. 사용자 실사용 판정이 가장 무겁다(2026-10-19, '검증됨' 상태를 없애고 성적표로 바꿈).

지식 파일의 내용은 사용자 경험이 출처다. 사용자가 말하지 않은 관찰이나 목표를 지어내 넣지 않는다. 추정한 건 `hypothesis`로, 출처를 밝혀서.

예외: `agent_usage`는 사용자가 판단하지 않는 분야라서 출처가 실측과 지휘 모델 기록이다(사용자 결정 2026-10-16). 목표만 사용자 것이고, 나머지는 AI가 사용자의 쌓는 방식을 따라 스스로 쌓는다. [agent_usage/CLAUDE.md](agent_usage/CLAUDE.md)
