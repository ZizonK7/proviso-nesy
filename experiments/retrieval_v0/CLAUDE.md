# experiments/retrieval_v0/ — 후보 뽑기 실험 v0

질문 글(작업 설명, 게임 사실)을 보고 논리집의 상태(조각 후보) 중 들어맞는 것을 작은 모델이 놓치지 않고 뽑는지 잰다.
목적(사용자 결정 2026-10-19): 비용 절감 확인이 아니라 **이 시스템을 쓸 때의 기대 효용을 높이는 연습** — 1종(헛짚음)·2종(놓침) 오류, 기본 비율, 조건부확률.

## 파일
- `data.py`: 정답지. agent_usage(`dispatches.toml` 작업 설명 → 상태), nonfiction_games(`games.toml` 사실 글 → 상태). '예'=양성, '아니오'=음성, '일부'·'모름'은 채점에서 뺀다.
- `scorers.py`: 점수 방법. `overlap`(지금 엔진의 낱말 겹침), `bigram`(글자 두 개 겹침) — 표준 라이브러리. `make_embed`(문장 임베딩) — 외부 패키지.
- `score.py`: 상위 k를 '뽑힘'으로 보고 재현율 P(뽑힘|예)·정밀도 P(예|뽑힘)·질문당 놓침·헛짚음·우연 기준·상태별 표, 비용 비율별 기대 효용 최대 k.
- `run.py`: 보고서. `python -m experiments.retrieval_v0.run [--embed <모델> --e5] [--out <파일>]`
- `requirements.txt`: 임베딩용 외부 패키지. **엔진(`proviso/`)은 표준 라이브러리만 유지** — 외부 패키지는 이 폴더에서만.

## 지킬 것
- 정답지는 논리집 기록 그대로 쓴다. 정답지가 틀린 것 같으면 실험 코드에서 고치지 말고, 논리집 기록을 고친 뒤 다시 돌린다(무엇을 왜 고쳤는지 기록).
- agent_usage의 상황 값 일부는 작업이 끝난 뒤에 채워졌다(dispatches.toml 머리말). 그리고 많은 상태는 작업 설명 글만 봐서는 알 수 없는 것이다(예: "비슷한 과거 작업이 있다"). 둘 다 점수를 낮추는 쪽이다 — 결과를 읽을 때 같이 적는다.
- 모델 이름·버전, 실행 환경(CPU/GPU)을 보고서에 적는다.
